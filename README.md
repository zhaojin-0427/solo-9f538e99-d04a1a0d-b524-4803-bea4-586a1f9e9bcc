# 联合目录同物凭证复核台

联合目录把不同藏品并成一件时，编目员需要判定应复核哪些同物凭证。本工具从 CSV
导入凭证供数，为选定的一对或两对编号计算**总复核工时最少**的停用清单，使每一对
编号都无法再经由有效凭证相连。

## 启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在命名卷 `catalog-data` 的 SQLite 文件中，容器重建不丢失。

本地直接运行：

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python wsgi.py            # http://localhost:8000
```

## CSV 格式

```csv
voucher_no,catalog_a,catalog_b,minutes,locked
V-1001,CAT-A100,CAT-B200,40,0
V-1002,CAT-A100,CAT-C300,75,0
```

* `minutes`：1～10000 的整数（预计复核工时，分钟）
* `locked`：`0`/`1`；锁定凭证不可停用
* 单个供数最多 2000 份凭证；整批校验通过才写入

## 求解模型

把编目号当顶点、有效凭证当带权无向边（权 = 复核工时）。要停用的凭证集合必须使
所选编号对不连通，即**最小多终端割**：

* 一对编号：最小 s-t 割（Dinic 最大流，精确）
* 两对编号：最优解总可表示为单一割；对“每对一个端点固定在源侧”的四种方式各求一次
  最小割并取最小，即为精确最优

因此不枚举停用组合，2000 份凭证也可瞬时求解。平行凭证（同一对编号的多份凭证）
各自计工时；锁定凭证按不可切断处理，必须切断锁定凭证才可行时判为无解。

## 确认语义

* 求解产出草稿清单，不立即改动供数；网页可随时查看。
* 求解期间可继续更正工时和锁定状态（求解读取一致性快照，不持锁计算）。
* 确认时在单个事务内按**当时的有效凭证**重新复查：清单中每份凭证仍有效且未锁定、
  仍能分离每一对编号、总工时仍等于当前最少值——三者同时满足才把凭证从供数撤下。
* 无解、确认被拒或写入失败：整体回滚，供数保持原样。

## 「替换全部供数」与求解任务的关系

替换导入在**单个事务**内完成：清凭证、清历史清单、把旧批次所有未完成任务
（`queued`/`running`）置为 `void` 并写入作废说明、供数代际
（`feed_generation`）加一。因此：

* **正在计算的旧任务会被中止**：worker 只有一个后台线程（至多同时跑一项求解），
  替换提交后通过取消事件通知求解器在检查点协作式中止（`SolveCancelled`），
  新供数的任务随后接着算。替换本身**不等待**旧求解结束（求解不持有数据库锁）。
* **迟到结果不生成清单**：worker 落库前会复查任务状态，已 `void` 的任务即使拿到
  结果也不会写 `plans`/`plan_items`。
* **排队中的旧任务不会拿新供数计算**：它们在替换事务内已被作废，永不执行。
* **重启不复活**：启动时只把崩溃遗留的 `running` 任务重新排队，`void` 任务保持作废。
* **过期表单拦截**：`/solve` 表单隐藏当前 `feed_generation`；替换前打开的表单提交时
  代际不一致，会提示刷新且不创建任务，即使新批次沿用相同编目号。
* **仅限替换**：替换失败（整批回滚）、合并导入、工时/锁定更正都不作废任务、不提升
  代际，已打开的表单与既有任务照常工作。

旧任务页（`/jobs/<id>`）与首页任务表会显示「已作废」标签和原因。
